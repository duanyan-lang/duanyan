# HardyScript 开发文档

## 一、项目定位

HardyScript 是一个 **交叉编译器**（Cross Compiler）：
- **运行环境**：宿主机（Windows x86_64）
- **目标输出**：COUNPRE64 32位机器码（.hex 文件）
- **输入**：JavaScript 子集源码

`
┌─────────────────────────────────────────────────────────┐
│  宿主机 (Windows x86_64)                                │
│                                                         │
│  JavaScript源码 → [HardyScript编译器] → COUNPRE64机器码(.hex) │
└──────────────────────────────────────┬──────────────────┘
                                       │ 烧录
                                       ▼
┌─────────────────────────────────────────────────────────┐
│  智能数卡 (Gowin GW1NSR-4C FPGA)                        │
│                                                         │
│  COUNPRE64 CPU @50MHz → 执行机器码 → 40 MIPS            │
└─────────────────────────────────────────────────────────┘
`

> **重要**：HardyScript 不是 no_std 程序！它是一个普通的 Rust CLI 工具，运行在宿主机上。

## 二、COUNPRE64 指令集参考（与 FPGA 实现对齐）

### 2.1 指令格式

**RR型（寄存器-寄存器）**：OP[3]=0
`
| 31-28 | 27-24 | 23-20 | 19-16 | 15-12 | 11-8  | 7-4   | 3-0   |
| OP(4) | RS1(4)| RS2(4)| RD(4) | FUNC(4)| RESV  | MODE  | SIGN  |
`

**RI型（寄存器-立即数）**：OP[3]=1
`
| 31-28 | 27-24 | 23-12      | 11-8  | 7-4   | 3-0   |
| OP(4) | RS(4) | IMM(12)    | RD(4) | MODE  | SIGN  |
`

**类型判别**：OP[3]=0 → RR型，OP[3]=1 → RI型

### 2.2 操作码分配（与FPGA decoder_v2.v 完全对齐）

| Opcode | 类型 | 指令 | 说明 |
|--------|------|------|------|
| 0x0 | RR | 创新指令 | FUNC区分: ADD(0),ROL(9),ROR(A),MAX(B),MIN(C),ABS(D),SWAP(E),SEL(F) |
| 0x1 | RR | SUB | 减法 |
| 0x2 | RR | AND | 按位与 |
| 0x3 | RR | OR | 按位或 |
| 0x4 | RR | XOR | 按位异或 |
| 0x5 | RR | SHL | 逻辑左移 |
| 0x6 | RR | SHR | 逻辑右移 |
| 0x7 | RR | MUL/DIV | FUNC区分: MUL(8),MULH(9),DIV(C),DIVU(D),REM(E),REMU(F) |
| 0x8 | RI | ADDI | 加立即数 |
| 0x9 | RI | ANDI | 与立即数 |
| 0xA | RI | ORI | 或立即数 |
| 0xB | RI | LOAD | 内存加载 |
| 0xC | RI | STORE | 内存存储 |
| 0xD | RI | BEQ/BNE | 条件分支 (MODE区分) |
| 0xE | RI | JUMP/JAL | 无条件跳转 |
| 0xF | — | 保留 | 未来扩展 |

### 2.3 寄存器约定

| 寄存器 | ABI名 | 用途 |
|--------|-------|------|
| x0 | zero | 硬连线零 |
| x1 | ra | 返回地址 |
| x2 | sp | 栈指针 |
| x3-x7 | t0-t4 | 临时寄存器 |
| x8-x11 | a0-a3 | 函数参数/返回值 |
| x12-x14 | s0-s2 | 被保存寄存器 |
| x15 | fp | 帧指针 |

## 三、编译流水线设计

`
Phase 1          Phase 2          Phase 3          Phase 4
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  Lexer   │ →  │  Parser  │ →  │ Compiler │ →  │ Emitter  │
│ 词法分析  │    │ 语法分析  │    │ 代码生成  │    │ 输出hex  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
  JS源码           Token流          AST           指令列表      .hex文件
`

### 3.1 Lexer（词法分析器）
将 JS 源码切分为 Token 流：
- 关键字：let, function, if, else, while, return
- 运算符：+, -, *, /, =, ==, !=, <, >
- 字面量：整数、字符串
- 标识符：变量名、函数名

### 3.2 Parser（语法分析器）
将 Token 流解析为 AST（抽象语法树）：
- 递归下降解析（Recursive Descent）
- 支持的语法子集（Phase 1）：
  - 变量声明：let x = expr;
  - 赋值：x = expr;
  - 算术表达式：a + b * c
  - 函数声明：function foo(a, b) { ... }
  - if/else
  - while 循环
  - return

### 3.3 Compiler（代码生成器）
将 AST 编译为 COUNPRE64 指令序列：
- 寄存器分配（简单线性扫描，16个寄存器）
- 表达式求值 → ALU 指令
- 变量 → 寄存器映射或栈存储
- 控制流 → 分支/跳转指令

### 3.4 Emitter（输出器）
将指令序列编码为最终格式：
- .hex 文件（可直接烧入 FPGA program_rom）
- 汇编文本（调试用）
- 二进制（原始机器码）

## 四、开发计划

### Phase 1：最小可用编译器（MVP）

**目标**：编译 let a = 10; let b = 20; let c = a + b; 生成正确 .hex

| 任务 | 模块 | 说明 |
|------|------|------|
| 1.1 | 项目重构 | 去除 no_std，改为普通 CLI 程序 |
| 1.2 | ISA模块 | 对齐 FPGA 实际编码格式 |
| 1.3 | Lexer | 词法分析：数字、标识符、运算符、关键字 |
| 1.4 | Parser | 语法分析：let声明、算术表达式 |
| 1.5 | Compiler | 代码生成：表达式→COUNPRE64指令 |
| 1.6 | Emitter | 输出 .hex 文件 |
| 1.7 | 验证 | 编译结果烧入FPGA，串口验证执行 |

### Phase 2：控制流

| 任务 | 说明 |
|------|------|
| 2.1 | if/else → BEQ/BNE 分支 |
| 2.2 | while → JUMP 循环 |
| 2.3 | 比较运算符 (==, !=, <, >) |
| 2.4 | 逻辑运算符 (&&, ||) |

### Phase 3：函数调用

| 任务 | 说明 |
|------|------|
| 3.1 | function 声明与调用 |
| 3.2 | 栈帧管理 (SP/FP) |
| 3.3 | 参数传递 (a0-a3) |
| 3.4 | return 返回值 |

### Phase 4：高级特性

| 任务 | 说明 |
|------|------|
| 4.1 | 数组/对象（堆内存） |
| 4.2 | 字符串处理 |
| 4.3 | console.log → UART 输出 |
| 4.4 | 优化 pass（常量折叠、死代码消除） |

## 五、使用方式（目标）

`ash
# 编译 JS 文件为 COUNPRE64 hex
hardyscript compile hello.js -o hello.hex

# 查看生成的汇编
hardyscript compile hello.js --emit-asm

# 直接烧录到 FPGA（通过串口）
hardyscript flash hello.js --port COM3
`

示例输入 hello.js：
`javascript
let a = 10;
let b = 20;
let c = a + b;
`

期望输出 hello.hex：
`
800A1000   // ADDI x1, x0, 10
80142000   // ADDI x2, x0, 20
01233000   // ADD  x3, x1, x2
`

## 七、与 COUNPRE64 CPU 的集成验证

编译器生成的 .hex 可以直接替换 FPGA 工程中的 program_rom.v 初始化内容：

`erilog
// program_rom.v - 由 HardyScript 生成
initial begin
    rom[0] = 32'h800A1000;  // ADDI x1, x0, 10
    rom[1] = 32'h80142000;  // ADDI x2, x0, 20
    rom[2] = 32'h01233000;  // ADD  x3, x1, x2
end
`

验证流程：
1. hardyscript compile test.js -o test.hex
2. 将 hex 写入 program_rom.v
3. Gowin IDE 综合 → P&R → 烧录
4. PowerShell 串口读取验证执行结果
