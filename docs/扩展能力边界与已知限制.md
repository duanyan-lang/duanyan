# 扩展 1-4 能力边界与已知限制

> 适用版本：DUANYAN v1.6.0（扩展 1-4 已合入 `main`）
> 目的：明确四个语言扩展"能做什么、不能做什么、为什么"，把编译期拦截规则一次讲清，降低踩坑率。
> 阅读对象：使用 `duanyan build` 编译到嵌入式/裸机目标的语言用户。

DUANYAN 是**真 AOT 编译器**（非片上 JS 解释器）。四个扩展的共同设计原则是：

- **确定性优先**——所有能力都必须在编译期把内存占用与循环次数钉死，不引入运行期动态分配或不定长循环。
- **旁路提取，不改宿主语法**——类型/寄存器注解在词法剥离（strip）之前从源码旁路扫描提取，经旁路表送入代码生成器，**不进 AST**。这保持了语法解析器冻结；扩展 1 的宽度表已升级为 **(名字, 行号)→类型 + 作用域栈**，同名变量按作用域隔离（H1 已根治，见扩展 1）。
- **越界即编译错误**——能在编译期发现的错误（字面量越界、除零、位域越位、f32 小数、链式降级等）一律**编译期报错**，绝不静默生成错误代码。

## 扩展 1：宽度安全整数（`u8/u16/u32/i8/i16/i32`）

### 语法

```javascript
let r: u8 = 200;        // 生成 uint8_t r = (uint8_t)(200);
let n: i16 = -300;
r = 12;                 // 赋值自动截断：r = (uint8_t)(12);
```

### 能力

- 声明处按宽度发射精确 C 类型（`uint8_t`/`int16_t`/…），缺省为 `int32_t`。
- **字面量越界编译期 lint**：`let r: u8 = 300;` 直接报错（300 超出 `[0,255]`），不会静默截断成 44。
- 赋值处插入截断转换前缀（`(uint8_t)` 等），语义与 C 一致。

### 已知限制

- **【H1｜已根治】宽度类型按作用域隔离，同名变量互不干扰。**
  旁路候选表的键为 **(变量名, 声明行号)**；代码生成器维护**作用域栈**（顶层/模块作用域为栈底，每个函数叠加独立作用域），在声明点按 `(name, line)` 命中候选表并绑定到当前作用域，查询时**由栈顶向外层逐层解析**。因此同名变量在不同函数/作用域各自独立：`function a(){ let r: u8 }` 发射 `uint8_t`、`function b(){ let r }` 发射 `int32_t`，互不影响（旧的“同名即全局回退 int32_t”保守补丁已移除）。
  - 已知边界（第一阶段）：**函数级 + 顶层**作用域粒度，同一函数内的块级遮蔽暂不区分；`.ts` 跨行 `interface`/`type` 块被剥离会压缩行号，致其后声明行号偏移、宽度绑定可能失配（`.js` 不剥离，行号天然对齐，无此问题）；多行函数签名的形参宽度暂不绑定。
- 类型注解仅对 `let/const` 声明与其后的赋值生效；不覆盖函数返回值推断、对象字段等。

## 扩展 2：寄存器位域（`@register` + masked RMW）

### 语法

```javascript
// 位域格式：字段名: [hi, lo]（高位在前），hi/lo 均须落在 [0,31] 且 hi >= lo
@register(0x40004000) const GPIO_OUT = { en: [1, 1], val: [7, 2] };

GPIO_OUT.en = 1;        // 写：读-改-写，只动 bit1，不影响其他位
let x = GPIO_OUT.val;   // 读：((GPIO_OUT >> 2) & 0x3F)
```

### 能力

- 声明**不占存储**（发射为占位注释 `/* @register ... */`），位域在访问点直接展开为寄存器地址操作。
- **写 = masked RMW**：`REG = (REG & ~((uint32_t)mask << lo)) | (((uint32_t)v & (uint32_t)mask) << lo);`——只改目标位段。
- **读 = 掩码提取**：`((REG >> lo) & mask)`。
- **【L1】全程 `uint32_t`**：清位掩码也转 `uint32_t` 再移位，避免触及 bit31 时裸 `int` 左移的实现定义行为（UB）。

### 已知限制

- **【L2】位域索引越界即报错。** `hi > 31` 或 `hi < lo` 会被 `parse_bit_range` 拒绝（返回 `None`），防止 `>>` 越位 UB。位域必须落在单个 32 位寄存器内。
- **【H1｜重要】`@register` 名不可与普通变量/对象同名。** 若某 `@register` 名又被普通 `let/const` 声明，触发**重复声明编译错误**——因为旁路表按名全局生效，同名会被误展开为裸寄存器写。
- 仅支持 32 位寄存器（`DUANYAN_REG32`）；不支持跨寄存器的位段拼接。

## 扩展 3：定点 `q15/q16` 与受控浮点 `f32`

### 语法

```javascript
let a: q15 = 2;
let b: q15 = 3;
let p: q15 = a * b;     // (int32_t)(((int64_t)a * (int64_t)b) >> 15)
let d: q15 = a / b;     // (int32_t)(((int64_t)a << 15) / (int64_t)b)
let x: f32 = 1;         // float x = (float)(1);  ← 注意：只能是整数字面量
```

### 能力

- `q15/q16` 以 `int32_t` 原始存储；乘除用 **64 位中间量**（`int64_t`）防溢出，再移位回标度。
- `f32` 作为**受控浮点逃生舱**，面向有 FPU 的目标（如 ESP32-S3），发射为 C `float`。

### 已知限制

- **【H2｜最重要】`f32` 不能直接赋小数字面量——会编译报错。**
  DUANYAN 词法层把**小数字面量统一 ×100 缩放为整数**（`1.5` → `150`，最多 2 位小数），这是定点优先的底层约定，`Number` token 无法区分 `1.5` 与 `150`。因此：
  - `let x: f32 = 1.5;` → **编译报错**（否则 `x` 会被静默赋成 `150.0`，错得离谱）。
  - `let x: f32 = 1;` / `let x: f32 = someExpr;` → 正常发射 `float`。
  - **要表示真小数，请改用 `q15/q16` 定点**；这是当前唯一能忠实表达小数值的途径。
- **【M2】`q15` 与 `q16` 不能混合运算。** 标度不一致（15 vs 16）无法确定移位量，混合定点运算**编译报错**。
- **定点 × 普通整数：走普通算术，不移位**（这是**有意行为**，非 bug）。例如 `q15 × 普通int` 结果标度仍是 15，无需移位；只有**两侧同为定点且同标度**时才触发 `>>15`/`<<15` 重写。
- 定点移位重写仅在**标识符 × 标识符**时触发（`fixed_shift_of` 只认 `Ident`）；字面量参与的定点表达式按普通整数处理。

## 扩展 4：数组高阶方法（`map/filter/forEach/reduce/slice`）

### 语法

```javascript
let arr = [1, 2, 3, 4];

let doubled = arr.map(x => x * 2);            // let/const 初始化位置
let evens   = arr.filter(x => x % 2 == 0);
let total   = arr.reduce((a, x) => a + x, 0); // (累加器, 元素) => 表达式, 初值
arr.forEach(x => print(x));                   // 语句位置
let sub     = arr.slice(1, 3);                // 子区间拷贝
```

### 能力

- 全部**降级为静态长度的确定性 C `for` 循环**（回调内联、回调次数 = 数组长度、结果缓冲 `static`）。
- `slice` 起止索引按 **JS 语义 clamp**（负索引 `+= len`，再夹到 `[0, len]`），杜绝越界读。

### 已知限制

- **【H3｜重点·链式限制】`filter`/`slice` 的结果不能再做高阶方法。**
  `filter`/`slice` 的结果长度是**运行期值**（`filter` 命中几个才知道几个），编译期不确定，无法静态降级为确定性循环。因此把它们登记为"运行期长度数组"，**再对其调用 `map/filter/reduce/forEach/slice` 会编译报错**。
  - 反例（报错）：`arr.filter(x => x>0).map(x => x*2);`
  - 正解：拆成两步，且第二步的源是**静态长度数组**。
- **【L5】只能出现在语句位置或 `let/const` 初始化位置。**
  放在任意表达式位置（函数实参、二元运算操作数、`return` 等）或嵌套调用，一律**编译报错**。
  - 反例（报错）：`print(arr.map(x => x*2));`、`arr.map(x=>x*2).filter(...);`
- **回调必须是箭头函数**，且 `map/filter/reduce` 的回调必须是**表达式体**（`x => expr`），不支持块体 `{ ... }`。
- **仅对静态已知长度的数组生效**（数组字面量 `[1,2,3,4]`）；对运行期长度数组（含 `filter`/`slice` 结果）不支持。
- **【M3】`reduce` 的累加器名与元素名不能相同**（如 `(a, a) => ...` 报错）；当 `reduce` 结果名与累加器名相同时，累加器即结果，不再重复声明（防 C 变量重定义）。
- `slice` 与字符串方法 `slice` 同名：**只有当对象确为已知数组时**才按数组高阶方法处理，不会误伤 `str.slice()`。

## 附：编译期拦截一览（遇到报错先查这张表）

| 触发条件 | 归属 | 报错含义 |
|---|---|---|
| 宽度字面量超范围（`u8 = 300`） | 扩展 1 | 字面量越界，非静默截断 |
| 同名变量在不同函数各带/不带宽度注解 | 扩展 1｜H1（已根治） | 按作用域隔离，各自正确发射（不再全局回退） |
| `@register` 名与普通变量同名 | 扩展 2｜H1 | 重复声明冲突 |
| 位域 `hi > 31` 或 `hi < lo` | 扩展 2｜L2 | 位域越界，拒绝 |
| `f32` 变量赋**小数**字面量 | 扩展 3｜H2 | 词法 ×100 缩放冲突，改用 q15/q16 |
| `q15` 与 `q16` 混合运算 | 扩展 3｜M2 | 标度不一致 |
| 对 `filter`/`slice` 结果再做高阶方法 | 扩展 4｜H3 | 运行期长度，无法静态降级 |
| 数组高阶方法出现在表达式位/嵌套 | 扩展 4｜L5 | 只支持语句位或 let/const 初始化 |
| `map/filter/reduce` 回调非箭头/非表达式体 | 扩展 4 | 回调形式受限 |
| `reduce` 累加器与元素同名 | 扩展 4｜M3 | 参数冲突 |
| 除数为字面量 `0` | 通用｜L3 | 编译期拦截除零 |
| `async x => ...` 裸参数箭头 | 通用｜L6 | 请写成 `async (x) => ...` |

## 设计说明：为什么是“旁路表”，以及 H1 的根治

扩展 1/2/3 的类型与寄存器信息**没有进 AST**，而是在词法剥离前从原始源码旁路扫描提取（`strip.rs::extract_width_types` / `extract_registers`），经 `generate_c_source_with_ext` 注入代码生成器拦截发射。

- **收益**：不必给 AST 每个表达式节点加类型字段，避免引爆解析器与生成器里大量的穷尽 `match`，扩展开发快、回归面小。
- **曾经的代价（H1 的根源）**：旁路表原为“**按名全局、无作用域**”，同名变量在不同作用域被视作同一个。
- **已根治（中期重构第一阶段）**：`extract_width_types` 现返回 **(变量名, 声明行号)→类型** 候选表；代码生成器以 `SourceStatement.line` 为锚，在声明点绑定到**作用域栈**（`width_scope`），查询走 `lookup_width` 由内向外逐层解析——扩展 1 的宽度同名冲突从根上隔离，旧的“保守回退”补丁已删除。扩展 2 的 `@register` 名冲突仍以**重复声明报错**处理（寄存器无作用域概念，保持原状）。

> 本文档随扩展演进同步维护；如发现描述与实际编译行为不符，请以 `src/c_codegen/`（`mod.rs` / `ext.rs` / `hal.rs` / `hw_helpers.rs`）、`src/strip.rs` 的实现与 `src/c_codegen_tests.rs` 的回归用例为准，并回报修订。
