# DUANYAN 机器人对齐升级计划 v1.6

> 目标版本：v1.5.2 → **v1.6.0**
> 缘起：DuanYanX 决策引擎 v1.5 已给真机装上 `joint_api`（PCA9685 颈 + ZX361 总线臂 + 回读 + 包络）、`safety_policy`（负载/温度/堵转护栏）、mode-B 协议扩展（0x24/0x30/0x31）。DUANYAN 作为「JS→固件」编译器，其机器人/舵机层与这台真机**对不上**：只有直连引脚 PWM 玩具舵机、无 I²C  expander、无总线舵机、无回读、安全模型是另一套、运动学是孤岛、且不认识 mode-B 脑体分离。本计划把 DUANYAN 从「能驱动通用舵机」升级到「能驱动这台真机」，并顺带打通锻言 LLM 生成真机代码。

## 1. 总体原则

1. **对齐而非另造**：P0/P1/P3 的 Rust 模型以 DuanYanX 对应模块为口径移植/镜像，命名保持一致（除 `EscalatePi`→`EscalateHost` 这类去项目专名），并加**字节级/数值级一致性测试**，防止两边漂移。
2. **编译器语义**：DUANYAN 是编译器不是运行时——关节/安全/轨迹能力落点是「JS 面 → `HardwareCall`/绑定表 → `generate_hw_helpers` 吐 C helper + 调用点落 C」。绑定表在**运行期 C 表**（沿用 `hardy_servo_*` 运行期钳位风格），Rust 侧模型负责编译期校验/lint/仿真/测试。
3. **不破坏既有**：新能力全部走**新 `hardy:*` 模块 + 新 `HardwareCall` 变体**，默认构建（无 `domains`）也可用；`robotics.rs` 的重工业/ISO 部分保持 `domains` 门禁不动，只把**纯轨迹/FK 数学**下沉到无门禁新模块供编译器路径复用。
4. **逐 target 递进**：C helper 先落 **ESP32 / Esp32S3Bare**（真机在用），Arduino/STM32/RPi 作为后续补齐（本轮至少保证不编译报错、可留 TODO 桩）。
5. **每步绿**：每个 P 项自带单测；P0→P3 逐项 `cargo test` 与 `cargo test --features domains` 双绿后再进下一项。

## 2. P0 — 关节/舵机模型对齐 `joint_api`（最高价值）

### 2.1 JS 面（新模块 `hardy:servo`，关节为中心）
```js
const { Joint } = require("hardy:servo");
// 绑定表：关节号 → 后端 + 包络（编译期收集 + 运行期 C 表）
Joint.bind(0, { name:"pan",  backend:"pca9685", channel:0, min:30, max:150, home:90 });
Joint.bind(1, { name:"tilt", backend:"pca9685", channel:1, min:60, max:125, home:90 });
Joint.bind(4, { name:"shoulder", backend:"zx361", id:2, min:0, max:240, home:120 });
Joint.write(0, 90);          // 自动钳到包络，路由 PCA9685 CH0
Joint.write(4, 120, 500);    // 总线舵机，500ms 行程
let pos = Joint.read(4);     // 总线：位置真值；PWM：hw 脉冲/不可用
Joint.home();                // 全归中
```

### 2.2 Rust 侧（新增无门禁模块）
- `src/bus_zx361.rs`：从 DuanYanX 移植（自包含 ASCII 构造/解析，171 行量级）。供 `deg_to_bus_pwm`、codegen 字符串测试、P3 复用。**移植后加断言测试与 DuanYanX 输出逐字节一致**（`move_cmd(1,1500,500)=="#001P1500T0500!"` 等 6 例）。
- `src/joint_api.rs`：镜像 DuanYanX——`Backend`、`JointSpec`、`JointCmd`、`JointApi{new,bind,neck_as_built,spec,clamp_deg,deg_to_bus_pwm,readback_kind,set_deg→(Backend,载荷),read_kind}`。`name` 用 `String`（DUANYAN 是 std 宿主）。
- `hardware_api.rs`：
  - `HardwareModule` 增 `Servo`（`from_import_source("hardy:servo")`）。
  - `HardwareCall` 增 `JointBind{joint,backend,chan_id,min,max,home}`、`JointWrite{joint,ms}`、`JointRead{joint}`、`JointHome`（角度/时间多为运行期表达式，走调用点 `generate_expr`，故 `HardwareCall` 只承载可常量化的元数据；实际 C 参数在调用点拼）。
  - `resolve_hardware_call` + `hardware_call_to_description` 补对应分支。

### 2.3 codegen 接线（`c_codegen.rs`，精确落点）
- **import 扫描**（~L401 `HardwareModule::Motor` 旁）：新增 `HardwareModule::Servo => hw_imports.insert(format!("servo:{}", item))`，item ∈ {Joint,Pca9685,BusServo}。
- **includes**（~L675 ESP32 / ~L707 Arduino）：`hw_imports` 含 `servo:*` 时，ESP32 加 `driver/i2c.h`（PCA9685）+ `driver/uart.h`（ZX361）。
- **`generate_hw_helpers`**（ESP32 分支 ~L895 起、Esp32S3Bare 分支）：当含相应 import 时吐：
  - `hardy_pca9685_init(addr)` / `hardy_pca9685_write_us(channel, us)`：标准 PCA9685 序列（MODE1 睡眠/唤醒、50Hz 预分频、`LEDn_ON=0`、`LEDn_OFF = us*4096/20000`）。
  - `hardy_zx361_move(id, pwm, ms)` / `hardy_zx361_read_pos(id)` / `hardy_zx361_read_temp(id)`：UART 上拼 `#IDPppppTtttt!` / `#IDPRAD!` / `#IDPRTE!`（ASCII，与 bus_zx361 一致）。
  - 关节层：`hardy_joint_bind(idx, backend, chan_id, min, max, home)`、`hardy_joint_write(idx, deg, ms)`（**运行期钳位包络** → 路由：PCA9685 走 deg→pulse_us→pca_write；ZX361 走 deg→bus_pwm→zx361_move）、`hardy_joint_read(idx)`、`hardy_joint_home()`。
- **调用点**（表达式 codegen match，~L1888 `"Servo.attach"` 旁）：加 `"Joint.bind" | "Joint.write" | "Joint.read" | "Joint.home"` 分支，用 `generate_expr` 拼实参落 `hardy_joint_*(…)`。

### 2.4 测试
- `joint_api.rs`：镜像 DuanYanX 7 例（bind 拒非法/倒置包络、clamp、deg_to_bus_pwm 端点、neck_as_built 通道/包络、readback_kind、PWM/BUS 路由）。
- `bus_zx361.rs`：移植 6 例 + 与 DuanYanX 字节一致断言。
- `hardware_api.rs`：`from_import_source("hardy:servo")==Servo`、`resolve_hardware_call("Joint.write",…)`。
- `c_codegen_tests.rs`：给一段 `require("hardy:servo")` + `Joint.bind/write` 的 JS，断言生成 C 含 `hardy_joint_write`、`hardy_pca9685_write_us`、`hardy_zx361_move`、包络钳位注释、`driver/i2c.h`。

### 2.5 验收
`duanyan build arm.js --target esp32s3`（及 `esp32`）产出的 C 能以关节号驱动 PCA9685 颈 + ZX361 臂，带包络钳位与回读；上述测试全绿。

## 3. P1 — 安全模型收敛（负载/温度/堵转护栏）

### 3.1 Rust 侧（新增无门禁 `src/robot_safety.rs`）
移植 DuanYanX `safety_policy.rs`：
- `SafetyLimits{load_max:u16=900, temp_max_c:f32=65.0, stall_ms:u32=3000}`（Default 同值）。
- `SafetyAction{None, TorqueOff(u8), Stop(u8), AlarmLed, EscalateHost}`（`EscalatePi`→`EscalateHost` 去专名）。
- `evaluate(id,load,temp_c,stall_ms,limits)`：优先级 **temp>stall>load**；`stall_ms==0||u32::MAX` 视为无堵转证据。
- `check(...)`：迟滞——故障置 faulted，恢复需连续 `NORMAL_RECOVER=3` 次正常，期间返 `EscalateHost`；`is_faulted`、`clear`。
- **与 `robotics.rs` 关系**（文档写清、两处交叉引用）：`robotics::safety_check` = ISO/TS 15066 **人机碰撞**力/速层；`robot_safety` = **执行器**负载/温度/堵转层；二者互补，非替代。

### 3.2 JS 面 + codegen
- `const { Safety } = require("hardy:servo")`：`Safety.limits({load_max,temp_max_c,stall_ms})`、`Safety.check(load,temp,stall_ms)` → 动作。
- `generate_hw_helpers`：含 servo/joint import 时吐 `_hardy_safety_check(load, temp_c, stall_ms)`（同优先级 + 迟滞静态状态），限额用 `#ifndef HARDY_LOAD_MAX / HARDY_TEMP_MAX / HARDY_STALL_MS` 便于编译期覆盖。`hardy_joint_read` 读温度/负载时可串接该检查。

### 3.3 测试
镜像 DuanYanX safety_policy 6 例（优先级、迟滞恢复、faulted、TorqueOff/Stop/EscalateHost）+ codegen 测试（C 含 `_hardy_safety_check`、`#ifndef HARDY_LOAD_MAX`）。

### 3.4 验收
生成的机器人固件默认带负载/温度/堵转护栏，语义与 daemon 侧 `safety_policy` 数值一致（测试保证）。

## 4. P2 — 轨迹/运动学暴露为 `hardy:robot`（复用现有 tested 数学）

### 4.1 去门禁下沉
- 新增无门禁 `src/robot_motion.rs`：把 `robotics.rs` 的**纯数学**（`plan_quintic`/`sample_quintic`/`plan_trapezoidal`/`forward_kinematics`）下沉为单一真源；`robotics.rs`（domains）改 `use crate::robot_motion`，只保留阻抗/ISO/融合等垂直扩展。**保证默认构建可测**。

### 4.2 JS 面
```js
const { Traj, Joint } = require("hardy:robot");
let h = Traj.quintic(30, 120, 2.0);   // q0,qf,T
let s = Traj.sample(h, 1.0);           // {pos,vel,acc}
Joint.glide(0, 30, 120, 2.0, 20);      // 五次采样 20 点平滑移动（呼应真机 0x23 track glide / 50°/s slew）
```

### 4.3 codegen
`generate_hw_helpers`（含 `robot:*` import 时）吐自包含 C：`_hardy_quintic_plan/_hardy_quintic_sample/_hardy_trapezoid_plan/_hardy_joint_glide(idx,from,to,T,steps)`（逐采样点 `hardy_joint_write` + 延时）。调用点加 `"Traj.quintic"|"Traj.sample"|"Joint.glide"` 分支。

### 4.4 测试
`robot_motion.rs` 单测（镜像 robotics.rs 现有 quintic/trapezoidal/fk 断言，防下沉回归）+ codegen 测试（C 含 `_hardy_joint_glide`）。

### 4.5 验收
`hardy:robot` 在**默认构建**（无 domains）可用；`Joint.glide` 生成平滑多点轨迹 C；`cargo test` 与 `cargo test --features domains` 双绿（robotics 下沉后不退化）。

## 5. P3 — mode-B 协议绑定 + `--target duanyan-spine`

### 5.1 Rust 侧（新增无门禁 `src/modeb_proto.rs`）
- 命令常量镜像 DuanYanX：`0x01 HEARTBEAT / 0x02 SENSOR / 0x10 LED / 0x12 STATUS / 0x20 JOINT_SET / 0x21 JOINT_QUERY / 0x22 ARM_POSE / 0x23 TRACK / 0x24 PLAY_QUERY / 0x30 ARM_SYNC / 0x31 ARM_ASCII`。
- `Frame{cmd,payload}` + `encode()` → `[AA,55,len,cmd,…,cksum]`：**校验和算法逐字节移植 `DuanYanX/src/mode_b_proto.rs`（单一真源）**。
- **一致性测试**：对已知帧断言字节完全相同（心跳 `[AA,55,04,01,00,00,00,00,C6]`、状态 `[AA,55,00,12,7E]`、joint_set、track 各一例），防两端漂移。

### 5.2 JS 面 + codegen
- `const { ModeB } = require("hardy:modeb")`：`ModeB.frame(cmd,payload)`、`ModeB.jointSet(j,deg)`、`ModeB.armSync([...])`、`ModeB.send(frame)`（UART 上带 `8×'U'` 校准突发 + 帧，与真机位啮时序一致）。
- `generate_hw_helpers` 吐 `_hardy_modeb_send(cmd, payload, len)`（组帧 + 校验和 + UART 写 + 前导突发）。

### 5.3 `--target duanyan-spine`
- `CTarget::from_str` 增别名 `"duanyan-spine" | "spine"` → 复用 `Esp32S3Bare` 项目生成路径，额外注入 **mode-B 应答端骨架**（收帧→解析 cmd→分发 0x20/0x21/0x22/0x23→PCA9685/ZX361 执行→回 ACK/0x24 状态）。
- **诚实边界**：本轮只产**骨架/scaffold**；真机 `uart_linkm6.bin` 的位啮 UART 时序仍是权威，未经实测证明前不替换。0x24/0x30/0x31 的**固件应答端 bring-up 属 DuanYanX 侧待窗**，P3 提供的是 host/编译侧与 spine 骨架。

### 5.4 测试
`modeb_proto` 字节一致测试（vs DuanYanX 已知帧）+ codegen 测试（C 含 `_hardy_modeb_send`、`AA 55` 前导、`'U'` 突发）。

### 5.5 验收
JS 能经 `hardy:modeb` 生成 mode-B 发帧代码（与 daemon 同协议同字节）；`--target duanyan-spine` 产出含 mode-B 应答骨架的 S3 裸机项目。

## 7. 排期与依赖

## 8. 风险与不做项

- **不做**：重写真机 S3 固件；替换 `uart_linkm6.bin` 位啮时序；本轮不保证 Arduino/STM32/RPi 的新 helper 完整（先 ESP32/S3Bare，其余留桩不报错）。
- **风险**：PCA9685/ZX361 的 C helper 为**字符串级单测**（沿用现有 servo helper 的测试口径），上电实测属独立 bring-up；mode-B 校验和若移植有偏差会被「字节一致测试」当场拦下。
- **诚实口径**：完成后 DUANYAN 能**编译期表达并生成**驱动这台真机的代码；真机运行验证仍需后续 hardware-in-the-loop（与 DuanYanX 侧 0x24/0x3x bring-up 同窗）。
